# 场景壁纸实时渲染：覆盖率与性能实测

0.6.0 的「场景实时渲染」上线前，在本机真实壁纸库（Steam 创意工坊 431960 下 **100 张** `type=scene`
的壁纸）上跑了一轮全量实测。结论：**100 / 100 张都能在页面里渲染出首帧**，帧率中位数 28–56fps
（取决于测法），只有 4 张重场景在 60fps 目标下低于 30fps。下面是可复现的方法与踩过的坑。

## 测试方法

| 项 | 值 |
| --- | --- |
| 渲染器 | `vendor/webwallgl/webwallgl.min.mjs`（webwallgl 2.1.0） |
| 资源 | WE API 服务只读路由 `http://127.0.0.1:8088/files/<id>/…`（`project.json` + `scene.pkg`） |
| 浏览器 | Chrome `--headless=new --use-angle=d3d11 --enable-gpu`（**不弹窗口**） |
| 渲染后端 | ANGLE (AMD Radeon 780M, D3D11) —— headless 里也是真 GPU，不是 SwiftShader |
| 画布 | 1280×820 CSS；`--window-size=1280,820` |
| 每张流程 | `mount()` → 首帧落地 → 采样 1.5s 读 `wp.stats.fps` → `dispose()` → 等 80ms |
| 会话隔离 | **每 10 张换一个全新浏览器会话**（见下方「坑 2」） |
| 结果落盘 | 每张测完立刻 POST 到本地服务，写成 JSONL（浏览器崩了也不丢数据） |
| 环境 | Windows 11 build 26200 · 2560×1440 · 笔记本双显卡（测试走的是核显 780M） |

脚本（本机 PoC，未随包发布）：`.tmp-scene-poc/coverage.mjs` + `sweep.html`（跑法见文末）。

## 结果

**覆盖率：100 / 100（100%）**，0 失败。每张都成功走到「首帧已画出」。

首帧耗时（`mount()` 从调用到 resolve）：

| p50 | p90 | max | 慢于 3 秒 |
| --- | --- | --- | --- |
| 1008ms | 3468ms | 7325ms | 12 张 |

帧率（`fps: 30` 上限，顺序连测 —— 这是**保守下界**，原因见坑 3）：

| 分档 | 张数 |
| --- | --- |
| ≥ 28fps（顶到上限） | 52 |
| 20–28fps | 31 |
| < 20fps | 17 |

**那 17 张单独复测**（每张一个全新会话、`fps: 60` 上限）：p50 = **55.6fps**、max 60.3fps，其中
13 张回到 40–60fps；只有 4 张确实重：

| 壁纸 ID | 独立实测 fps（60 上限） |
| --- | --- |
| 3554906812 | 16.7 |
| 3742497499 | 22.0（首帧也慢，6.1s） |
| 3588734957 | 22.1 |
| 3012085161 | 28.2 |

这 4 张在插件里会由 `autoQuality` 在连续 3 秒低于上限 85% 后自动降后处理 / 粒子 / 分辨率；
用户也可以把「场景帧率上限」降到 30 或更低。

## 三个坑（都踩过，记下来免得重踩）

1. **「成功」的定义是 `mount()` resolve**，也就是渲染器确认首帧已画出 —— **不等于**像素级复刻
   WE 官方画面。逐张保真度没有做自动比对（抽查截图里，角色立绘、粒子、光斑、场景文字对象都正常）。
2. **一个浏览器会话里连续挂载多张会撞 Chrome 的 WebGL 上下文上限**：第一轮扫描（每会话连挂 80 张）
   在后半段开始每张都报 `WEBGL2_UNAVAILABLE`，mount 只用 30–500ms 就失败，得出过「成功率 62%」的
   假结论 —— 而其中被判定失败的 `3797976859` 单独实测稳定 60fps。渲染器的 `dispose()` 确实调了
   `WEBGL_lose_context`，但释放跟不上连续创建。**测法修正：每 10 张换一个全新会话**，之后
   100/100 全通过。
   - 对插件本身的影响：正常使用时一张壁纸会停留很久，且切走时 `dispose()` 在淡出结束后立即释放；
     只有在**极快地连续点选十几张场景**时才可能偶发一次回退预览图 —— 这是设计内的优雅降级
     （面板会写明原因），不是错误。
3. **顺序连测的帧率明显偏低**：同一张壁纸在连测里 7.7fps、单独测 59.7fps。会话内的上下文 / 显存
   累积会拖慢后续每一张。**要测真实性能必须一张一个会话**；连测数字只能当保守下界看。

## 复现

```powershell
# 1) 起本地 PoC 服务（提供工坊文件 + 结果落盘端点）
cd .tmp-scene-poc
node server.mjs                       # 监听 127.0.0.1:8791

# 2) 全量覆盖（headless、每 10 张换会话、结果写 .tmp-shots/scene-sweep.jsonl）
node coverage.mjs --max=10 --sample=1500 --timeout=15000 --deadline=1200

# 3) 单张独立测性能（每张全新会话，排除累积影响）
node perf.mjs "<id>,<id>,..." 8000
```

结果文件：`.tmp-shots/scene-sweep.jsonl`（每行一张：`{id, ok, mountMs, fps, frames, err, quality}`）。
